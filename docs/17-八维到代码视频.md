# 八维方法层 · 从"描述"到"代码视频"

> 八维公式原本是写给**演员**的（AI 演戏：目的、情绪、AU、目光……）。
> 代码视频里没有演员，但有**导演**。同一套八个方面，平移成八个可以拧的旋钮，就变成了"描述即生成"的接口。
>
> 实现：`scripts/render_codevideo.py`｜示例：`examples/丝绸之路.codevideo.yml`

---

## 一、八个方面，以及它们在代码里是什么

| # | 八维原文 | 代码视频里的对应物 | 拧动它会怎样 | 接线状态 |
| --- | --- | --- | --- | --- |
| 1 | 时间段 | 每拍的 `time: [起, 止]` | 决定这一拍多长、字幕何时进出 | ✅ 已接线 |
| 2 | 人物目的 | `purpose`：这一拍要让人**感到**什么 | 参与选场景，也是你改片时的判断依据 | ◐ 弱接线 |
| 3 | 情绪 A → B | `emotion: 安静 → 辽阔` | 整段色调从 A 色漂到 B 色 | ✅ 已接线 |
| 4 | 台词触发词 | `trigger` + `line` | 字幕里这几个字变强调色 | ✅ 已接线 |
| 5 | 面部动作 | `detail`：画面里最具体的那一层 | 目前只写给人看，没驱动渲染 | ○ 待接线 |
| 6 | 目光与身体 | `composition`：主体在哪、留白在哪 | 同上 | ○ 待接线 |
| 7 | 声音、呼吸与停顿 | `sound`：铺底/扬起/留白 | 背景乐是统一合成的，未按拍变化 | ○ 待接线 |
| 8 | 结束状态与禁止 | `end` / `forbid` | 同上 | ○ 待接线 |

**说清楚**：现在真正驱动画面的只有 4 项（时间、情绪、触发词、场景词）。另外 4 项是**给人看的约束**——它们不影响这一次渲染，但决定了你写的时候有没有想清楚，也决定了以后往哪接线。

我不想把它们包装成"全都实现了"。

## 二、填空模板

```yaml
title: 标题
fps: 24

beats:
  - time: [0, 6]                     # ① 时间段，精确到 0.5 秒
    purpose: 先给"远"，不给知识         # ② 目的：这一拍要让人感到什么
    emotion: 安静 → 辽阔               # ③ 必须有箭头，两端都得是词
    trigger: 一条路                    # ④ 落在哪个词上
    line: 从长安出发，向西              #    字幕正文
    scene: 公路                        # ⑤ 场景词：公路/星空/台灯信/花枝/江面/窗/雨窗
    detail: 路面向远处收束，电线杆变小   # ⑥ 画面里最具体的一层
    composition: 主体压左，右侧留白      # ⑦ 主体位置
    sound: 低音铺底，进入时一声风        # ⑧ 声音
    end: 停在路的尽头，人不出画
    forbid: 不要出现人；不要高饱和；不要字幕压路面
```

七个场景的关键词：`窗 / 雨窗 / 台灯信 / 公路 / 星空 / 花枝 / 江面`。
写别的词会按 `场景 → 台词 → 目的` 的顺序去猜，猜不到就按拍数轮换。

## 三、跑一条

```bat
python scripts\render_codevideo.py examples\丝绸之路.codevideo.yml out\丝绸之路.mp4
```

实测：5 拍 / 30 秒 / 1080p24，**212 秒渲完，11.1 MB**，带合成配乐。

渲染器只做四件事：

1. 按 `time` 切段，取对应场景的图层，逐层生长（每层淡入 0.75s，长句压缩）
2. 按 `emotion` 的 A/B 两色，整段做 20% 权重的色调漂移
3. 按 `trigger` 给字幕里那几个字上强调色
4. 加雾、粒子、暗角、颗粒、镜头缓推，压到 1080p

## 四、这套方法真正解决什么

以前做一条片子，是"调参数试出来"：改个色、看一版、再改。三十秒的片子渲三分钟，试错成本很高。

八维的作用是**先把话说清楚再渲**：

| 写之前必须回答 | 回答不了会怎样 |
| --- | --- |
| 这一拍多长？ | 五拍均匀切，节奏像 PPT |
| 目的是什么？ | 画面好看但不知道在讲什么 |
| 情绪从哪到哪？ | 全片一个色调，像滤镜没换 |
| 落在哪个词上？ | 字幕整句一样重，没有落点 |
| 结束帧停在哪？ | 每拍都演满，剪起来没有气口 |
| 禁止什么？ | 上一拍的毛病下一拍继续犯 |

**最容易忽略的是第 8 维（结束状态与禁止）。** 它不产生画面，但它是唯一能防止"越改越乱"的一维——每次渲完对照一遍禁止项，比反复微调有效。

## 五、局限

- **没有真正的构图控制**。`composition` 写"主体压左"，画面不会真的左移。要做得改场景函数。
- **没有声音设计**。配乐是统一合成的一段，不随拍变化。`sound` 字段暂时是备忘。
- **场景只有七个**。写第八种意象只能等新场景函数。
- **没有字级同步**。触发词只是变色，不是随唱随亮。

---

## 六、接线顺序（下一步最该做的三件）

1. **`composition` → 主体位置**：给场景函数加一个 `anchor` 参数，左/中/右三种构图，成本最低、收益最大
2. **`sound` → 音乐分段**：把 `make_music` 拆成"铺底 / 扬起 / 收薄"三档，按拍切换
3. **`end` → 落幅时长**：让每拍最后 0.3–0.6 秒静止（不推进镜头），剪辑点会干净很多

`forbid` 最难接线，但它可以变成一个**渲后自检脚本**：跑一遍色域检测，看看有没有用到禁止的颜色——这比让人眼盯着看靠谱。
