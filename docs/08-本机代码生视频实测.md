# 本机「代码生视频」能力实测

> 测试时间 2026-10-30 晚｜机器：i5-1135G7 / 15.8 GB / Iris Xe + MX450 2 GB / Win10 19045
> 所有数字都是跑出来的，不是估的。脚本见 `scripts/render_bench.py`、`scripts/bench_moviepy_vs_pipe.py`。

---

## 一句话结论

**代码生视频：完全可行，1080p 能到 1–2 倍实时。**
**AI 生视频：不行，而且不是"慢"，是 CUDA 运行时根本没装。**

---

## 一、硬件真相：CUDA 是缺的

| 检查项 | 结果 |
| --- | --- |
| GPU | NVIDIA GeForce MX450，**2048 MB 显存** |
| 驱动 | 30.0.15.1213 → **512.13（2022 年 3 月）** |
| `nvidia-smi` | **不存在** |
| `nvcuda.dll` | **缺失**（CUDA 驱动 API，torch / 任何 GPU 计算都靠它） |
| `nvml.dll` | **缺失**（所以没有 nvidia-smi） |
| `nvapi64.dll` | 存在（只是显示相关） |
| NVENC 硬编码 | 失败：`Cannot load nvcuda.dll` |
| 设备状态 | PnP 里是 `OK`，即"能显示"，但**没装计算组件** |

`DriverStore` 里其实躺着 `nvlt.inf_amd64_.../nvml.dll`，说明驱动包里有 CUDA 组件、只是没被安装。

**这意味着：装 torch 也调不起 GPU，装 ComfyUI 也跑不了。** 不是显存不够的问题，是驱动这一层就断了。

> 修法（需要你手动操作，我不动系统）：去 NVIDIA 官网下载 MX450 对应的 **Studio/Game Ready 驱动**重装，
> 装完 `C:\Windows\System32\nvcuda.dll` 才会出现。但即便修好，**2 GB 显存仍然跑不了任何视频模型**（最低 8 GB 起）。

## 二、编码能力：够用，但不是瓶颈

10 秒 1080p30（300 帧）纯编码耗时：

| 编码器 | 耗时 | 速度 |
| --- | --- | --- |
| libx264（CPU，preset medium） | 3.9 s | **2.5x 实时** |
| h264_qsv（Intel Iris Xe 硬编） | 4.0 s | 2.5x 实时 |
| h264_nvenc（MX450） | — | **不可用** |

结论：**别折腾硬件编码，x264 已经在 2.5 倍速**，QSV 省不了多少。瓶颈永远在"怎么把像素算出来"，不在"怎么压成 mp4"。

---

## 三、代码渲染：这才是本机的强项

### 测法 A：纯绘图层（渐变 + 圆环 + 文字 + 进度条），1080p30

| 指标 | 数值 |
| --- | --- |
| 帧数 | 300（10 秒） |
| 耗时 | 4.50 s |
| 速度 | **66.6 fps ＝ 2.2x 实时** |
| 推算 30 秒片 | **约 13.5 秒** |

### 测法 B：真实用途「节拍预览片」（文字卡片 + 时间轴），720p30

| 指标 | 数值 |
| --- | --- |
| 帧数 | 900（30 秒） |
| 耗时 | 38.1 s |
| 速度 | **23.6 fps ＝ 0.79x 实时** |

结论：**画面越"文字密集"，越慢**（PIL 的字体渲染是主要开销）。纯图形 2.2x 实时，满屏小字 0.8x 实时。
按这个区间估：**一分钟 1080p 的代码视频，30 秒到 80 秒能渲完。**

## 四、MoviePy 到底慢不慢？实测推翻了印象

拿**完全相同的画法**（同一套 Pillow 绘制函数），各渲 90 帧 1080p：

| 写法 | 耗时 | 速度 |
| --- | --- | --- |
| 直接 `subprocess` 管道喂 ffmpeg | 1.73 s | 52.1 fps |
| MoviePy 2.1.2 `VideoClip(lambda t: ...)` | 1.78 s | 50.6 fps |
| —— 额外开销 | | **1.0x** |

**MoviePy 2.x 几乎不产生额外开销。** 之前记录的"3.5 fps"不是 MoviePy 的锅。

### 那 3.5 fps 是哪来的？

`video-projects/moviepy-demo/starter.py` 的 `wave_frame()` 每帧都做 **1080p 全分辨率逐像素 numpy 运算**：

```python
y, x = np.mgrid[0:H, 0:W]                              # 每帧重建 2×1920×1080 数组
wave_y = (H/2) + 190*np.sin(x/W*3.2*math.pi + t*2.0)   # 2M 像素算 sin
dist = np.abs(y - wave_y)
glow = np.clip(1.0 - dist/110.0, 0, 1) ** 2            # 2M 像素乘方
```

实测这段函数本身：**223.8 ms/帧 ＝ 4.5 fps**。和文档记录的 3.5 fps 吻合（加上合成与编码）。

### 三级优化实测

| 写法 | ms/帧 | fps | 提升 |
| --- | --- | --- | --- |
| 原始 | 223.8 | 4.5 | — |
| ① 静态层缓存（背景、渐变只算一次） | 158.3 | 6.3 | 1.4x |
| ② ①＋低分辨率算光晕再放大（1/4） | **68.2** | **14.7** | **3.3x** |

两条都是通用手法：**能提前算的不进循环，能用低分辨率算完再放大的别在原尺寸算。**

## 五、和 D 盘那套栈的关系

`D:\video-stack`（ffmpeg 9.0.2 / node 22.12 / python 3.11 venv / moviepy 2.1.2 / manim 0.22）**确实装好了，版本也对得上**。
示例工程在 `C:\Users\LX\Documents\deepseek-harness\default-workspace\video-projects\`，三个 demo 的产物都在。

三处需要更正/补充：

1. **"MoviePy 3.5 fps"应改为"该示例的画法 4.5 fps"** —— 换个画法 MoviePy 能到 50 fps，framework 不是瓶颈。
2. **"无 CUDA 运行时"要说得更具体**：`nvcuda.dll` / `nvml.dll` 缺失 + 驱动 512.13（2022 年），
   所以连 NVENC 硬编码都用不了。这不是性能问题，是组件没装。
3. **补一组可用区间**：代码渲染 1080p 在 **0.8x–2.2x 实时**之间，取决于文字密度。

## 六、本机真正该干什么

| 能做，而且快 | 不能做 |
| --- | --- |
| 字幕卡 / 片头片尾 / 转场 | 文生视频、图生视频 |
| 数据动画、图表、算法可视化 | 任何需要 CUDA 的推理 |
| **节拍预览片（animatic）** | 本地跑 ComfyUI / Wan / LTX |
| 批量模板出片（一条命令几十条） | 实时 3D 渲染 |
| 自动剪辑、拼接、压制、抽帧质检 | —— |

一句话：**把本机当"剪辑台 + 分镜板"，把生成外包给云。**

## 七、顺带做出来的功能

`aiacting animatic` —— 把 YAML 直接渲成节拍预览片，**不花一分积分**就能看节奏对不对：

```bat
aiacting animatic examples\what-about-my-life.yml -o animatic.mp4
aiacting animatic examples\what-about-my-life.yml --plan    :: 只出文本节拍表
```

画面里是每个节拍的目的 / 情绪曲线 / 触发词 / 面部 / 目光 / 声音 / 停顿 / 禁止项，
底部一条时间轴实时高亮当前节拍。**用来判断"这条 30 秒的情绪曲线成不成立"，比看文字快得多。**
